## 2. 建议的核心论点
**一句话：** 学一个"可辨识、引擎可适配"的视频材质先验，把逐场景仿真拟合从小时级降到少量仿真次数，并能用少量样本迁移到新的物理引擎。

### 贡献（按稿件主次）
**C-A 摊销式先验 + 仿真闭环修正（主贡献，对应"先验加速在线拟合"）**
- 前馈先验给出可辨识量的分布（族后验 + 回归均值与不确定度），作为 CMA-ES 或可微仿真修正的初值和搜索协方差。
- 核心证据是"精度对仿真次数"曲线：先验 + k 次仿真 vs 无信息初值 + N 次仿真，在同一目标函数、同一几何下比较，报告加速比和物体级置信区间。这正面回应 xhp2 要求的"与物理反演方法协议对齐的比较"。
- 调研没有找到在多个引擎上系统报告"先验质量 → 达到目标精度所需的时间"的工作；Vid2Sim 只给了单引擎的 15 分钟对比 54–120 分钟。

**C-B 引擎条件化与 K-shot 跨引擎适配**
- 共享视频编码器（冻结 V-JEPA2）+ 引擎 token 或每个引擎一个轻量输出头。同名参数在不同引擎里含义不同（GAUGE 2608.05948 用真实测量证实了这一点），所以每个引擎学自己的参数头，跨引擎用"响应一致"来评估。
- 证据：MPM → libuipc FEM，K=0/4/8/16/32/全量的适配曲线，并且用目标引擎重新仿真，验证适配后的参数确实更好。原文用 500 次目标仿真做域适配，这次目标是 K≤32 就接近全量。
- 外部数据：PAC-NeRF 的 4 个有真实参数的场景作验证性检查（只当定性证据）。

**C-C 可辨识性分析与可辨识目标（支撑性贡献，也是"基准 V2"）**
- 理论 + 受控仿真说明哪些量能从视频读出，据此重新定义预测目标和评测：族、E/ρ、σ_y/ρ、ν 和删失标签，并用族内相关来评测；绝对的 E、ρ 需要已知的力或质量。
- 交互激励研究：阻尼、动作种类（press / 接触加载 vs tap / drop）对可观测性的影响，回应 xhp2 对加载方式和数据多样性的质疑。
- DeformFieldBench-V2：低阻尼、重力、6 种动作，独立 test 集；另加 uipc 子集，构成一个小的多引擎反演基准。调研显示目前没有"同一批物体、多引擎、带真实参数"的反演基准。

**不再主张的：** 物理场桥（降为消融）；绝对 E、ρ（改为在有力或质量信息时才给）。

### 关于几何
数字孪生的几何部分沿用现有重建（多视角 3DGS，原管线已有），论文写明"几何已知或由现成重建给出，贡献在材质"。没有时间做几何联合估计，在 limitation 里说明。

| 实验 | 判断 | 调整 |
|---|---|---|
| V2main B/C/D | 必要（先验本体），已基本完成 | 不再加 seed；结果作 C-C 与消融 |

| v3b-C1 闭环修正 | **最关键**，直接支撑 C-A | 已追加无信息初值对照（4/12/24/48 次仿真）和"用不确定度定搜索协方差"一组；优先保证 GPU |

| v3a uipc few-shot | 必要，支撑 C-B | 已追加引擎 token 联合训练、K=4/16 两点、用 uipc 重新仿真验证 |
| v3c 横向基线 | 必要（AKYF、xhp2 都要求） | DINOv3 B/C（≈原论文结构）、首帧静态、VLM、常数/族均值，再加"无信息初值的逐场景拟合"作为物理反演基线；PIXIE/VoMP 只在有空时做首帧推理 |

**结论：** 方向基本对，只是重心要从"场桥"转到"先验 + 闭环修正 + 跨引擎适配"。目前最大的风险在 C1：仿真慢，而且如果先验带来的加速不明显，主论点就会变弱。所以 C1 要优先占用 GPU，并且在 11-14 中午设检查点。

## 结果记录

### 11-13 08:40 UTC — 跨引擎 K-shot（v3a，MPM → libuipc FEM，uipc val 40 条，3 seeds）
设定：uipc 悬臂梁/板，末端加载—保持—释放，单一弹性族，5 个训练几何 / 2 个验证几何。目标 ln(E/ρ) 标准化 MAE（越低越好），Spearman 为 E 的秩相关。

| 方法 | K=0 | K=4 | K=8 | K=16 | K=32 | 全量 120 |
|---|---:|---:|---:|---:|---:|---:|
| MPM 先验直接迁移 | 1.176（Spearman −0.12） | | | | | |
| 仿射校准（只调输出尺度） | | 0.331 | 0.227 | 0.221 | 0.222 | 0.221 |
| MPM 头微调 | | 0.182 | 0.120 | 0.074 | 0.062 | 0.058 |
| 引擎 token 联合训练 | | 0.265 | 0.151 | 0.087 | 0.072 | 0.067 |
| **冻结 V-JEPA + 从头训练头** | | **0.099**（Spearman 0.97） | **0.079** | | | 参照 0.045 |
| 训练均值 | | 0.284 | 0.290 | | | |

结论（不利）：
1. MPM 训练的参数头不能直接迁移到 FEM：K=0 时整体偏低约 1.2 个标准差，秩相关接近 0。同名参数跨引擎不一致，与 GAUGE 的发现一致。
2. **MPM 先验没有带来 few-shot 收益，反而比从头训练差**：从头训练头在 K=4 时 MAE 0.099，好于微调的 0.182 和引擎 token 的 0.265。
3. 原因很可能是这个 uipc 任务太简单：单一族、单一动作、几何少，挠度与 E 近似单调，冻结的 V-JEPA 特征加 4 个样本就够了。
4. 对论文的影响：C-B 不能写成"MPM 先验加速跨引擎适配"。能成立的说法是"冻结的视频基础模型特征与引擎无关，每个新引擎只需 4–8 个样本训练一个轻量头"——但审稿人会认为任务太简单。要让 C-B 有说服力，需要在 uipc 上用和 MPM 数据同类的物体、动作和多个族再测一次；时间不够就把 C-B 降为辅助发现。
- 补充（11-13 v3a 最终报告）：一个不需要学习的线索——与首帧的平均像素差——在 val 上与 E 的 Spearman 就有 0.98，说明这个 uipc 任务过于简单，学到的高相关不代表物理理解。用预测参数在 uipc 里重新仿真：K=0 平均位移误差 19.9 mm，K=8 适配后 0.75–1.18 mm，K=32 为 0.77–0.92 mm，30/30 配对样本都优于 K=0。ν 在 uipc 上同样不可辨识（各方法 MAE 0.06–0.09 ≈ 训练均值）。论文中 C-B 最多写成"引擎相关的参数映射需要 4–16 个样本校准，冻结视频特征可跨引擎复用"，并如实说明任务简单。
