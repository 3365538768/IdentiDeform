# PAC-NeRF 外部 4 场景小样本核查（V3c，仅定性）

结果文件：`docs/v3c/PACNERF_FEWSHOT.json`。脚本：`scripts/v3c/pacnerf_extract.py`（解压）、`scripts/v3c/pacnerf_fewshot.py`（build / eval）。

## 数据与协议
- 来源：`data/external_datasets/pacnerf/pacnerf/data.zip` 中的 4 个命名场景 torus、bird、playdoh、cat。用 `python3 -I` 只解出 `all_data.json` 和 `r_<视角>_<帧>.png`，目录是新建的空目录 `data/external_datasets/pacnerf_v3c_extract/`（约 420 MB）。路径做了白名单校验，压缩包里的任何东西都没有执行。`oracle/`、`masiv/` 没有打开，`simulation_data.zip` 这次也没用到。
- GT（PAC-NeRF 论文表 1）：torus E=1e6, ν=0.3；bird E=3e5, ν=0.3；playdoh E=2e6, ν=0.3, τY=1.54e4；cat E=1e6, ν=0.3, τY=3.85e3。**数据里没有密度，这里假设 ρ=1000，四个场景相同**。所以 E/ρ 的“排序”只依赖“四个场景密度相同”这一条假设；绝对值误差（z）还额外依赖 ρ=1000。ρ 本身不计分。
- 视角：11 个固定相机按方位角取 3 个，规则是让三者之间的最小方位角间隔最大。规范三元组 t0=[4,6,7]（最小间隔 109°），另外两个互不重叠的三元组 t1=[1,5,8]、t2=[2,3,10] 只用于支持集扩充和视角敏感性检查。
- 帧：渲染帧 14 帧（24 fps，0–0.54 s），用最近帧重复扩到 64 帧，800→224 px。之后按 `prepare_vjepa_cache.py` 的方式抽 V-JEPA 2 ViT-L 特征（tubelet 2 → 32 步），时间单位为秒。
- 两种输入：`raw` 保留真实渲染背景；`bgsub` 用数据自带的背景帧 r_v_-1 做差分抠图，把物体放到黑底上，与 V2 一致（会残留少量地面阴影）。
- 模型：V2 main C 头的 3 个种子（configs/v2main/v2main_C_seed{17,29,43}，best_material.pt，按 val 选出），没有用 PAC-NeRF 数据重新训练。
- 留一场景适配：支持集为另外 3 个场景 × 3 个三元组，查询为留出场景的 t0。超参数事先固定，没有在查询场景上调：
  1. offset：每个参数加上支持集的平均残差；
  2. ridge_last_layer：对 param_head 最后一层做岭回归增量（λ = 1·mean‖h‖²，偏置不惩罚），同时用支持集的二分类交叉熵重拟 law_head；
  3. support_mean_baseline：完全不看视频，直接预测 3 个支持场景 GT 的均值，用作对照。
- 律类映射：PAC-NeRF elastic → jelly；PAC-NeRF plasticine（von Mises）→ 弹塑性。主指标是二分类（jelly 对 metal/plasticine）。

## 结果（K=0 直接迁移）
| 输入 | 种子 | E/ρ Spearman（4 场景） | 成对排序正确率（5 对，不含 torus=cat 并列） | σY 排序 playdoh>cat | 二分类律类正确率 |
|---|---|---|---|---|---|
| raw | 17 / 29 / 43 | 0.63 / −0.32 / −0.63 | 0.8 / 0.4 / 0.2 | 否 / 否 / 否 | 0.5 / 0.5 / 0.5（四个场景全判为 metal） |
| bgsub | 17 / 29 / 43 | 0.63 / 0.32 / 0.63 | 0.8 / 0.6 / 0.8 | 否 / 是 / 是 | 0.75 / 0.5 / 0.75 |
| bgsub 种子集成 | – | 0.32 | 0.6 | 是 | – |

- raw 输入下律类完全塌缩为 metal，E/ρ 的排序在不同种子间正负都有，可以视为无信息。说明真实背景是严重的域偏移。
- bgsub 下，bird 在 3 个种子里都被判为最软的场景（与 GT 一致），也都被判为 jelly。torus 多数被判成 metal（错）。playdoh、cat 中二者在部分种子里被判为弹塑性。
- 绝对值：E/ρ 系统性偏低约 1 个标准差（|z| 误差 1.0–1.4，约等于 E/ρ 被低估 10 倍）。可能原因是时间尺度（0.54 s 自由落体，V2 是约 4 s 的工具加载）、物体尺度，以及 ρ=1000 这个假设本身。
- 视角敏感性：同一场景在 3 个三元组上的 z_E 标准差为 0.01–0.56（bgsub），不能忽略。

## 结果（留一场景适配）
- offset / ridge 把 E 的 |z| 误差从约 1.0–1.4 降到 0.17–0.39，但不看视频的 support_mean_baseline 也有 0.29。也就是说，绝大部分改善来自整体标定（尺度偏移），不能证明模型对未见场景有额外信息。只有 bgsub 种子 29/43 的 offset（0.21 / 0.17）略好于这个对照，种子 17（0.39）更差。
- offset 不改变场景之间的相对位置，但每个查询用的是不同的偏移量，所以排序可能被打乱。bgsub 下 ridge/offset 的 Spearman 为 0.32–0.63。support_mean_baseline 的 Spearman 为 −0.95（它天然会把留出场景往其余场景的均值拉）。
- 重拟律类头反而更差（二分类正确率 0–0.25）：留一后支持集的类别是 2:1 不平衡，留出场景恰好属于少数类，这是 4 场景留一设计本身的问题。
- σY 只有 playdoh、cat 两个场景带屈服应力。留出其中一个时，支持集里只剩另一个，所以 σY 的适配基本没有意义。

## 结论（诚实表述）
- 这只是 4 个场景、每个场景 1 条自由落体序列的定性核查，不能做任何统计结论。
- 能说的：在背景与 V2 对齐（bgsub）后，V2 C 模型零样本对 E/ρ 排序有弱的正向信号（集成 Spearman 0.32，2/3 种子成对排序 0.8），bird 被稳定识别为最软、弹性；绝对标定差约 1 z，需要外部标定。
- 不能说的：小样本适配带来的误差下降不能算“迁移成功”，因为不看视频的均值对照能达到相近误差；律类迁移也不可靠。
- 若要写进论文：建议放附录，作为“跨引擎/跨动作的定性检查”，同时给出 raw 与 bgsub 两种结果和 support_mean 对照。
